# iTerm2 런처 설계

## 목표

`NaverMap.app`을 더블클릭했을 때 서버 로그가 기본 Terminal 대신 iTerm2 창에 표시되도록 한다. 기존의 서버 켜기/끄기 토글과 브라우저 열기 동작은 유지한다.

## 선택한 방식

iTerm2가 설치되어 있으면 iTerm2의 새 창과 기본 프로파일 세션을 만들고, 그 세션에 `cd __APP_DIR__ && /usr/bin/python3 main.py`를 실행한다. iTerm2가 설치되어 있지 않은 Mac에서는 기존 Terminal 실행으로 자동 대체한다.

별도의 iTerm 전용 앱을 만들거나 iTerm2 설치를 필수 조건으로 만들지 않는다. 사용자는 지금과 같은 `NaverMap.app`을 계속 사용하며, iTerm2를 삭제해도 런처가 깨지지 않는다.

## 동작 흐름

1. 앱은 포트 8000의 수신 프로세스를 확인한다.
2. 서버가 없으면 iTerm2 설치 여부를 확인한다.
3. iTerm2가 있으면 새 창의 기본 프로파일 세션에 서버 명령을 전송하고, 없으면 Terminal 새 창에서 같은 명령을 실행한다.
4. 잠시 뒤 기본 브라우저로 `http://localhost:8000`을 연다. 알림에는 실제로 사용한 터미널 이름을 표시한다.
5. 서버가 있으면 PID와 연결된 TTY를 확보한 뒤 서버를 종료한다.
6. 확보한 TTY와 일치하는 iTerm2 세션을 우선 닫고, 해당 세션이 없으면 기존 Terminal 창 탐색으로 마무리한다. TTY를 얻지 못해도 서버 PID 종료는 수행한다.

## 오류 처리

- iTerm2가 없거나 자동화 호출에 실패하면 Terminal로 실행을 시도한다.
- 종료 단계의 창/세션 정리는 실패해도 서버 종료 결과를 되돌리지 않는다.
- 앱 시작과 종료 모두 기존처럼 macOS 알림을 표시한다.

## 검증

- AppleScript를 `osacompile`로 컴파일하여 iTerm2 명령 문법을 검증한다.
- 빌드 스크립트로 `NaverMap.app`을 재생성하고 번들 존재를 확인한다.
- 실행 중인 서버를 훼손하지 않는 범위에서 생성된 AppleScript에 iTerm2 우선 실행과 Terminal 대체 분기가 포함됐는지 검사한다.

## 범위 제외

- iTerm2 프로파일 생성·변경
- 서버를 백그라운드 서비스로 전환
- 기존 주소 처리·네이버 저장 기능 변경
