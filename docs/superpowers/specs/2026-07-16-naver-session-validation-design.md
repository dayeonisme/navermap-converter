# 네이버 로그인 세션 검증 및 리디렉션 복구 설계

## 목표

`NID_AUT`만 남고 `NID_SES`가 만료된 세션을 로그인 상태로 오판하지 않는다. 리스트 생성 중 네이버 로그인 페이지로 이동해 iframe이 분리되더라도 세션 만료로 분류하여 기존 Chrome 쿠키 재가져오기 및 단일 재시도 경로를 실행한다.

## 원인

- 현재 `is_logged_in()`은 `NID_AUT` 하나만 존재하고 만료되지 않았으면 로그인으로 판단한다.
- 실패 당시 저장 쿠키에는 유효한 `NID_AUT`와 만료된 `NID_SES`가 함께 있었다.
- 네이버 지도는 내 장소 진입 시 로그인 페이지로 이동했고, 이동 완료와 iframe 클릭이 겹치면서 `Frame was detached`가 발생했다.
- `_create_list()`는 로그인 URL을 일부 시점에만 검사하고 일반 예외를 모두 `리스트 생성 실패`로 감싸므로, `main.py`의 `SESSION_EXPIRED` 재시도 분기가 실행되지 않았다.

## 세션 판정

- `NID_AUT`와 `NID_SES`를 필수 로그인 쿠키로 정의한다.
- 두 쿠키 모두 값이 있고, 명시적인 만료 시간이 현재보다 미래일 때만 유효하다.
- 만료 시간이 `-1`이거나 없는 세션 쿠키는 브라우저 세션 동안 유효한 것으로 취급한다.
- `is_logged_in()`, Chrome 쿠키 가져오기 전 검증, 수동 로그인 대기 판정에서 같은 헬퍼를 사용한다.
- Chrome에서 읽은 쿠키에 두 필수 쿠키가 없으면 가져오기 성공으로 처리하지 않는다.

## 리스트 생성 중 로그인 이동

- `_create_list()`의 기존 로그인 URL 검사를 유지한다.
- iframe 조작 중 일반 예외가 발생한 경우에도 현재 페이지 URL이 `nidlogin`이면 원래 예외 대신 `RuntimeError("SESSION_EXPIRED")`를 발생시킨다.
- 로그인 페이지가 아닌 상태의 선택자·iframe 오류는 기존 단계명과 원본 예외를 포함한 `리스트 생성 실패`로 유지한다.

## 재시도와 오류 처리

- `main.py`의 기존 동작을 유지한다: `SESSION_EXPIRED`를 받으면 현재 컨텍스트 쿠키를 지우고 Chrome 세션 가져오기를 시도한 뒤 저장을 한 번만 재시도한다.
- 무한 재시도는 추가하지 않는다.
- Chrome에도 유효한 두 쿠키가 없으면 기존 로그인 대기/타임아웃 흐름을 사용한다.

## 검증

- 두 필수 쿠키가 모두 유효하면 로그인으로 판정하는 테스트를 추가한다.
- `NID_SES` 누락 또는 만료 시 로그아웃으로 판정하는 회귀 테스트를 추가한다.
- Chrome 쿠키에 필수 쿠키가 모두 없으면 가져오기 실패로 판정하는 테스트를 추가한다.
- 리스트 iframe 클릭이 `Frame was detached`로 실패하고 페이지가 로그인 URL이면 `SESSION_EXPIRED`로 변환되는 테스트를 추가한다.
- 로그인 URL이 아닌 선택자 오류는 기존 `리스트 생성 실패 [단계]` 형식을 유지하는지 확인한다.
- 전체 테스트를 실행하고 실제 저장 흐름에서 Chrome 세션 재가져오기 이벤트 또는 정상 리스트 생성을 확인한다.
