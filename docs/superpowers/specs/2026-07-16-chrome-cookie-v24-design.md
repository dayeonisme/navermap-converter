# Chrome 쿠키 DB v24 복호화 설계

## 목표

Chrome 쿠키 DB v24에서 네이버 로그인 쿠키를 올바르게 복호화하여 Playwright에 추가할 수 있게 한다.

## 원인

- 실제 Chrome 쿠키 DB의 `meta.version`은 `24`이다.
- v24의 복호화된 쿠키 페이로드는 실제 값 앞에 `SHA-256(host_key)` 32바이트를 포함한다.
- 현재 복호화 코드는 이 접두사를 값으로 처리해 제어문자가 포함된 값을 반환한다.
- Playwright는 해당 값을 `Invalid cookie fields`로 거부하므로 Chrome 세션 가져오기가 실패하고 로그인 대기로 빠진다.

## 복호화 규칙

- DB의 `meta` 테이블에서 `version`을 읽는다. 메타 정보가 없거나 정수 변환에 실패하면 버전 `0`으로 취급한다.
- v24 이상은 PKCS#7 패딩 제거 뒤의 바이트열이 `SHA-256(host_key)`로 시작할 때만 앞 32바이트를 제거한다.
- v24 이상에서 접두사가 일치하지 않으면 해당 쿠키를 건너뛴다. 검증되지 않은 바이트를 쿠키값으로 사용하지 않는다.
- v23 이하의 형식은 기존과 동일하게 패딩 제거 후 전체 값을 사용한다.
- 복호화 실패와 개별 쿠키 건너뛰기는 기존처럼 전체 Chrome 쿠키 가져오기를 중단시키지 않는다.

## 검증

- 임시 SQLite DB에 `meta.version = 24`과 AES-CBC로 암호화한 쿠키를 만든다.
- 테스트 암호문에는 `SHA-256(host_key) + 실제 쿠키값`을 포함한다.
- `_read_cookies()`가 접두사 없이 실제 쿠키값만 반환하는지 확인한다.
- v23 DB는 접두사 제거 없이 기존 값이 반환되는지 확인한다.
- 실제 Chrome의 `NID_AUT`, `NID_SES` 값이 제어문자를 포함하지 않고 Playwright 컨텍스트에 추가되는지 값 노출 없이 확인한다.
