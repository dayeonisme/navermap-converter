# 주소 결과 직접 저장 설계

## 문제

네이버 지도 주소 검색이 `/address/` 페이지로 바로 이동한 경우, 기존 코드는 주소 대신 주변 첫 장소를 열어 저장하려 했다. 현재 장소 상세 화면에는 기존 `a.D_Xqt[aria-pressed]` 저장 버튼이 없어 모든 항목이 실패한다.

## 선택한 방식

`/address/` 결과는 주변 장소를 열지 않고 주소 카드의 `button.btn_favorite`을 사용해 주소 자체를 저장한다. 이 버튼은 실제 현재 네이버 지도 주소 결과에서 확인했다.

## 동작

1. 검색 결과가 `/address/`이면 `_save_address_page`를 바로 호출한다.
2. 주소 저장 버튼을 클릭하고, 생성한 리스트를 선택한 뒤 저장을 확정한다.
3. 성공 시 `success`, 버튼·리스트를 찾지 못하면 `failed`로 기존 진행 UI에 전달한다.
4. 일반 검색 결과의 단일·복수 후보 처리와 리스트 생성은 변경하지 않는다.

## 검증

- `/address/` 분기가 `_try_address_place`를 호출하지 않고 `_save_address_page`로 위임하는 단위 테스트를 추가한다.
- 실제 주소 검색을 읽기 전용으로 재현해 주소 저장 버튼이 존재함을 확인한다.
- 전체 회귀 테스트를 실행한다.

## 범위 제외

- 장소 상세 화면의 변경된 저장 UI 대응
- 자동 선택한 주변 장소 저장
- 네이버 리스트 생성·로그인 처리 변경
